import { Card, CardGrid } from '@astrojs/starlight/components';

AI coding agents can change an iOS app in minutes. They are much worse at knowing whether the change
works. `proof` is a small command-line tool that gives them, and you, the evidence.

<CardGrid>
	<Card title="Readable builds and tests" icon="document">
		`proof build` and `proof test` print each error with `file:line` and each failing test with its
		assertion. Nothing else.
	</Card>
	<Card title="Eyes and hands on the simulator" icon="laptop">
		`proof ui tree` shows the screen as text. `proof ui tap --id …` acts on it by accessibility
		identifier.
	</Card>
	<Card title="Before and after" icon="seti:image">
		`proof snap home --compare base` screenshots a screen and lists what changed compared with the
		branch your PR targets.
	</Card>
	<Card title="Every PR in a stack" icon="list-format">
		`proof test --stack` tests each branch of a stacked PR on its own and marks the one that broke
		something.
	</Card>
	<Card title="One report" icon="open-book">
		`proof packet --open` puts the build, tests and screenshots side by side in an HTML page.
	</Card>
	<Card title="Nothing in your repo" icon="approve-check">
		No SDK, no test target, no code in your app. Everything proof writes goes to `~/.proof`.
	</Card>
</CardGrid>

## Quick start

```sh
brew install carloshmartins/tap/proof    # 1. install
proof setup                              # 2. teach your agent to use it (installs the skill)
cd path/to/YourApp                       # 3. once per app
proof init --scheme YourApp --simulator "iPhone 16"
proof build                              # 4. try it
```

Then ask your coding agent for a change. It builds, tests and checks the screen with proof, and ends with a
report you can open with `proof packet --open`. More in [Install](start/install/) and
[Set up your app](start/setup/).
